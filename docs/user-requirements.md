# WStart 用户需求文档

## 1. 产品概述

WStart 是一个桌面快捷启动与全局快捷键管理工具。它以轻量、常驻、快速打开为核心目标，帮助用户通过鼠标、边缘唤出、托盘菜单和全局快捷键快速启动程序、目录、网址以及常用系统功能。

第一阶段以 Windows 为主要完整功能平台；macOS 和 Linux 先保证界面能正常显示和基础启动器能力，平台专属能力可逐步补齐。

## 2. 产品目标

- 提供类似“音速启动”的紧凑启动器界面。
- 支持快速维护程序、目录、网址三类启动条目。
- 支持全局快捷键启动条目，并尽量屏蔽同一次按键继续传递给系统或前台应用。
- 支持托盘常驻、单实例运行、窗口激活、边缘吸附隐藏与鼠标触边唤出。
- 支持安装版和便携版两种分发形式。
- 支持自动更新，安装版和便携版都能升级到 GitHub Release 中的最新版本。
- 支持多 Qt 版本、多编译器、多架构的构建体系，但默认 CI 只构建主要分发变体，以控制成本。

## 3. 目标用户与使用场景

- 个人用户在 Windows 桌面环境中快速打开常用程序、文件、目录和网址。
- 通过全局快捷键打开固定应用，例如 `Win+S` 启动指定软件。
- 将 WStart 吸附到屏幕顶部，平时隐藏，需要时移动鼠标到边缘快速唤出。
- 使用便携版在固定目录中直接运行，并在更新时保持目录名不变，仅替换必要文件。
- 使用安装版获得常规安装、卸载、开机自启动等体验。

## 4. 平台与兼容性需求

### 4.1 Windows

- Windows 是完整功能平台。
- 支持全局快捷键、托盘、开机自启动、系统右键菜单、创建桌面快捷方式、以管理员身份运行、边缘吸附隐藏等 Windows 专属能力。
- Qt 5.6.3 变体按支持 Windows XP 的目标组织。
- Qt 5.15.2 用于覆盖 Qt5 LTS 和 Windows 7 兼容诉求。
- Qt 6.8.3 用于 Qt6 LTS 主要版本。
- Qt 6.11.1 用于跟进最新 Qt6 发行版本。

### 4.2 macOS 与 Linux

- 第一阶段要求 UI 能正常构建、启动和显示。
- 不要求实现 Windows 专属的全局快捷键拦截、托盘细节、系统右键菜单等功能。
- 后续可以逐步补齐平台原生能力。

## 5. 主界面需求

### 5.1 窗口结构

- 窗口标题使用 WStart。
- 主程序图标应简洁清晰，突出 W、启动管理、快速打开应用的含义。
- 标题栏需要包含设置、最小化、关闭按钮。
- 关于对话框中必须能查看当前版本号。
- 窗口宽度按适合四列条目的密度设计，并可在稳定后锁定宽度。
- 窗口支持置顶，用于提高边缘唤出在全屏应用前的可用性。

### 5.2 顶部一级分类

- 一级分类固定为三个：程序、目录、网址。
- 分类位于顶部，不使用左侧分类栏。
- 三个分类按钮等宽，横向占满窗口，不留额外空隙。
- 分类图标显示在文字左侧。
- “文件夹”命名改为“目录”，减少文字宽度。
- 网址分类使用地球图标。
- 分类按钮视觉上采用类似 Tab 页效果：
  - 选中的分类按钮颜色与下方内容区背景一致。
  - 未选中的分类按钮与内容区有明显区分。
  - 分类按钮下边缘使用直角，不使用圆角。
- 分类图标大小、文字字体、字号、颜色可配置。
- 分组高度可配置。
- 分组文字默认 10 号字。

### 5.3 搜索区

- 搜索框位于分类区附近，并与下方二级分栏区域在视觉上保持一体。
- 搜索框高度应紧凑，不能占用过多垂直空间。

### 5.4 二级分栏

- 当前一级分类下显示多个二级分栏。
- 程序分类默认分栏：
  - 系统功能
  - 我的程序
- 目录分类默认分栏：
  - 系统目录
  - 我的目录
- 网址分类默认分栏：
  - 常用网址
  - 我的网址
- 程序的系统功能分栏需要内置常用系统功能，并使用对应功能图标。
- 目录的系统目录分栏需要内置常用系统目录，并使用对应目录图标。
- 二级分栏标题区与内容区背景应有轻微差异，便于识别层级。
- 每个分栏可以折叠和展开。
- 同一个一级分类下，同一时间只允许展开一个分栏。
- 点击或双击分栏标题可展开当前分栏，同时折叠其他分栏。
- 当前展开分栏占用窗口所有剩余空间；折叠分栏只显示标题。
- 分栏图标大小、文字字体、字号、颜色可配置。
- 分栏高度可配置。
- 分栏文字默认 8 号字，和条目文字默认大小一致。

## 6. 条目管理需求

### 6.1 条目分类

- 条目归属于一级分类和二级分栏。
- 添加或编辑条目时，类型由当前一级分类自动决定，用户不需要手动选择类型。
- 程序分类中可以添加：
  - `.exe` 程序
  - 普通文件，例如 Word 文档，运行时使用系统默认程序打开
  - 系统功能
- 目录分类中可以添加：
  - 目录
  - 普通文件，运行时使用系统默认程序打开
- 网址分类中添加 URL。

### 6.2 条目添加与编辑

- 可以在分栏空白区域右键添加条目。
- 可以通过拖放文件或目录到条目列表中自动创建条目。
- 拖放时根据拖入目标分类和文件类型自动生成对应条目。
- 添加 `.exe` 程序时：
  - 自动读取 exe 图标作为条目图标。
  - 自动使用 exe 文件名作为条目文字。
  - 工作目录默认设置为 exe 所在目录。
- 添加程序条目时显示程序路径、参数、工作目录等必要字段。
- 添加目录条目时显示目录路径等必要字段，不要求用户选择动作类型。
- 添加网址条目时显示 URL 等必要字段，不显示无关参数和工作目录字段。
- 快捷键字段可选，未设置快捷键也允许保存。
- 条目标题中不显示快捷键文本；快捷键信息可在 tooltip 中显示。

### 6.3 条目启动

- 鼠标左键单击条目即可打开目标。
- 双击条目也可以启动，不能破坏单击启动体验。
- 程序、文件、目录、网址均使用系统合适方式打开。
- 对只允许单实例运行的应用，再次通过快捷键或条目启动时，应尽量激活已有窗口并置于前台。

### 6.4 条目右键菜单

条目右键菜单需要包含：

- 运行
- 编辑
- 删除
- 以管理员权限运行
- 显示资源管理器菜单
- 浏览，在文件资源管理器中打开文件所在目录
- 桌面快捷方式，在桌面创建快捷方式
- 设置开机自启动

右键条目时不能触发条目启动，也不能误弹添加条目对话框。

### 6.5 条目外观

- 条目图标固定支持 32x32 px 的默认显示。
- 条目真实点击区域必须随配置的条目宽度和高度变化，不能只是增大间距。
- 条目支持以下外观配置：
  - 图标宽度和高度
  - 条目宽度和高度
  - 字体和字号
  - 水平间隔和垂直间隔
  - 文字一行或多行
  - 是否显示省略号
- 在设置界面调整条目外观后，应立即生效。
- 默认布局密度应能显示四列条目，并能完整显示至少 5 个汉字。
- 条目文本字号默认较小，历史目标为 8 号字。
- 条目文本优先完整显示，不应在空间足够时仍显示省略号。
- 当内容区存在空白时，条目整体应居中显示，不能明显左偏。

## 7. 分栏管理需求

### 7.1 分栏右键菜单

在二级分栏标题上右键，应显示：

- 新建栏目
- 修改栏目
- 删除栏目
- 栏目加密

### 7.2 分栏编辑

- 新建或修改分栏时可设置名称、图标、排序等信息。
- 删除分栏前需要确认。
- 如果分栏中已有条目，删除时需要明确提示会同时删除条目。

### 7.3 分栏加密

- 分栏支持设置或修改密码。
- 进入加密分栏时要求输入密码。
- 本次运行期间，已解锁分栏保持解锁状态。

## 8. 全局快捷键需求

### 8.1 快捷键录制

- 添加或编辑条目时可以录制快捷键。
- 录制带 Win 键的组合键时，不能弹出系统窗口，例如 `Win+V` 不应调出系统剪贴板。
- 当前已知历史问题是快捷键录制曾不稳定；后续应继续保持回归测试。

### 8.2 快捷键响应

- 使用 Windows 低级键盘钩子实现全局快捷键响应。
- 命中用户配置的快捷键后，应启动对应条目。
- 命中后应尽量吞掉同一次键盘事件，阻止它继续传给系统或前台应用。
- 带 Win 键的快捷键需要重点处理，避免触发开始菜单或系统默认行为。
- 快捷键触发应尽量做到按一次即可响应，避免需要重复按两次或三次。
- 对只允许单实例运行的应用，快捷键触发时如果窗口不在前台，应尽量激活并置顶到当前前台。

### 8.3 快捷键边界

- 用户态拦截不能承诺覆盖所有系统保留快捷键。
- 不承诺覆盖 `Ctrl+Alt+Del`、`Win+L`、UAC 安全桌面、登录界面等系统安全场景。
- 快捷键服务只处理配置了合法快捷键的条目。
- 未设置快捷键的条目必须能保存、显示和运行。

### 8.4 快捷键管理

- 需要提供 WStart 系统中维护的快捷键总列表。
- 需要提示快捷键冲突风险。
- 可以提供快捷键占用情况查询能力，用于判断某些组合是否可能被系统或其他软件占用。
- 对“强制禁用其他应用快捷键占用”的能力需要谨慎处理：
  - 用户态只能尽量抢先拦截。
  - 不应承诺能禁用其他软件或系统的所有快捷键占用。

## 9. 托盘与窗口行为

### 9.1 托盘常驻

- 程序启动后常驻托盘。
- 关闭主窗口时默认隐藏到托盘，不退出程序。
- 托盘图标应能表达快捷启动或启动管理含义。
- 托盘右键菜单支持中文和英文动态切换。
- 托盘菜单至少包含：
  - 打开主窗口
  - 启用全局快捷键
  - 退出

### 9.2 单实例运行

- 应用只能启动一个实例。
- 当已有实例运行时，再次启动程序应激活已有窗口。
- 如果窗口隐藏或不在前台，应显示并尽量激活到前台。

### 9.3 边缘吸附隐藏

- 支持移动到屏幕顶部时自动吸附。
- 吸附到边缘后，如果鼠标仍在窗口区域内，不应立即隐藏。
- 吸附到边缘且鼠标离开窗口区域后，才触发隐藏。
- 鼠标移动到屏幕边缘时，应自动弹出整个窗口。
- 自动吸附需要稳定，避免出现吸不住或误隐藏。
- 在全屏 Edge 等应用场景下，应尽量通过置顶等方式保证边缘触发可用。

## 10. 设置需求

设置入口位于标题栏按钮中。设置项至少包括：

- 启用或禁用全局快捷键。
- 语言切换：中文、English。
- 皮肤切换：跟随系统、亮色、暗色。
- 是否开机自启动 WStart。
- 条目外观配置。
- 分栏外观配置。
- 分组外观配置。

设置变更应保存到本地配置，并在下次启动后保持。

## 11. 开机自启动需求

- 设置中提供是否开机自启动 WStart 的配置项。
- 开启后，随操作系统启动自动启动 `WStart.exe`。
- 开机自启动后应自动最小化或隐藏，不打断用户。
- 关闭设置后应移除对应开机自启动项。

## 12. 多语言需求

- 默认语言为中文。
- 支持 English。
- 主窗口、设置菜单、托盘菜单、分栏菜单、条目菜单、对话框、提示文本都应使用统一文本接口。
- 切换语言后立即刷新当前界面。
- 用户自定义的条目名称、分栏名称不自动翻译。

## 13. 皮肤需求

- 支持跟随系统、亮色、暗色三种模式。
- 默认跟随系统。
- 系统主题变化时，如果当前设置为跟随系统，应自动切换应用皮肤。
- 亮色和暗色皮肤下，分类、分栏、条目、菜单、标题按钮都应保持可读和协调。

## 14. 配置与数据持久化需求

### 14.1 配置存储

- 使用本地 JSON 配置。
- 配置存储在用户 AppData 或平台等效目录。
- 重启后保留条目、分栏、设置、外观、语言、皮肤、快捷键启用状态等信息。

### 14.2 核心数据结构

条目需要包含：

- `id`
- `enabled`
- `category`
- `sectionId`
- `hotkey`
- `action`
- `description`

分栏需要包含：

- `id`
- `category`
- `name`
- `iconKey`
- `sortOrder`
- `encrypted`
- `passwordHash`
- 外观和折叠状态相关字段

应用设置需要包含：

- `language`
- `hotkeysEnabled`
- `themeMode`
- `autoStart`
- 条目外观配置
- 分组外观配置
- 分栏外观配置

### 14.3 配置迁移

- 旧配置缺少字段时应使用合理默认值。
- 旧条目应按动作类型迁移到程序、目录或网址分类下的默认分栏。
- 非法枚举值应回退到默认值。

## 15. 自动更新需求

### 15.1 更新源

- 使用 GitHub Release 作为更新分发源。
- 当前私有仓库场景下，客户端可使用用户配置的 fine-grained PAT 访问私仓 Release。
- 客户端检查更新时默认访问 GitHub latest Release API：
  - `https://api.github.com/repos/weaver2007/WStart/releases/latest`
- 不依赖代码库中的固定 `update.json` 文件作为唯一入口。
- Release 中需要包含完整 `update.json` 和对应平台资产。

### 15.2 更新检查

- 客户端应能识别当前版本和最新版本。
- 如果 Release 清单缺少可下载资产，应显示明确错误。
- 不能把 Release HTML 页面当作安装包或压缩包下载。
- GitHub latest Release 必须指向最新稳定版本。

### 15.3 安装版更新

- 安装版使用动态库编译并制作 exe 安装包。
- 更新时下载新的安装包并执行安装流程。
- 安装包风格参考微信或 QQ，尽量简洁。

### 15.4 便携版更新

- 便携版使用静态库编译并打包为压缩包。
- 更新时保持当前目录名不变。
- 新版本文件应解压到临时目录后，再替换当前目录中需要更新的文件。
- 不能删除整个旧软件目录后导致新版本找不到。
- 支持运行中替换自身：
  - 主程序下载更新包。
  - 启动辅助更新器。
  - 主程序退出。
  - 辅助更新器替换文件。
  - 替换完成后启动新版本。
- 更新完成后再次检查更新，应显示当前已是最新版本。

## 16. 构建与发布需求

### 16.1 构建系统

- 使用 CMake 管理构建过程。
- 形成可迁移的多变体构建项目管理体系。
- 支持 MSVC 和 MinGW 两种工具链。
- 支持动态 Qt 和静态 Qt 两种依赖方式。
- 支持 x86、x64、arm64 等架构，具体以平台和工具链实际支持为准。

### 16.2 Qt 版本策略

保留必要 Qt 版本支持：

- Qt 4.8.7：覆盖 Qt4 系列和老系统兼容诉求。
- Qt 5.6.3：用于最后一代 Windows XP 目标构建。
- Qt 5.15.2：用于 Qt5 最后 LTS 和 Windows 7 目标。
- Qt 6.8.3：用于 Qt6 LTS。
- Qt 6.11.1：用于跟进最新 Qt6 发布版。

非 LTS 且无特殊目的的版本可以清理，不作为长期维护变体。

### 16.3 构建变体命名

构建变体命名应体现：

- Qt 版本
- 编译器和版本
- 链接方式：dynamic 或 static
- 架构：x86、x64、arm64
- 系统目标，例如 xp
- 构建类型，例如 release

示例：

- `qt6.11.1-msvc2022-dynamic-x64-release`
- `qt5.6.3-msvc2015-xp-static-x86-release`
- `qt4.8.7-msvc-dynamic-x86-release`

### 16.4 CI 策略

- 主分支上传时不自动触发构建 Action。
- 默认只构建 Windows x64 便携版或主要分发变体，以节省 GitHub Actions 时间。
- 全量构建通过手动触发或指定 tag 触发。
- 支持 Windows、macOS、Linux 的 x64 和 arm64 构建目标。
- Windows arm64、macOS arm64、Linux arm64 根据 runner 和工具链条件实现。
- 构建产物需要上传为 GitHub Actions artifact，并在 Release 中发布。

### 16.5 发布版本

- 通过 tag 触发发布构建。
- Release 中需要包含安装版和便携版资产。
- latest Release 应只指向当前最新版本。
- 新版本发布后，应能被客户端自动更新检查发现。

## 17. 版本与命名需求

- 产品名称统一为 WStart。
- 历史名称 HStart、HotKeyManager 应在用户可见文本、构建产物、Release、安装包等位置逐步替换为 WStart。
- 仓库名称和远端路径应统一为 WStart。
- 版本号使用语义化风格，例如 `0.3.23`。
- tag 使用 `v` 前缀，例如 `v0.3.23`。

## 18. 图标与视觉资产需求

- 主程序图标应简洁、清晰，能表达启动管理和快速打开应用。
- 可以突出 W 和启动管理含义。
- 可以体现快捷键快速打开，也可以不体现快捷键。
- 图标边缘留白应尽量少，核心区内容更大。
- 任务栏图标、窗口左上角图标、托盘图标应保持一致。
- Qt4 版本也应正确加载 ico 和 svg 插件，保证图标显示一致。
- 系统功能和系统目录需要使用语义明确的对应图标。

## 19. 安全与权限边界

- Windows 上全局快捷键和部分系统功能可能需要管理员权限。
- 用户态快捷键拦截不能突破系统安全边界。
- 不承诺拦截登录界面、安全桌面、UAC、安全组合键等场景。
- 私有 GitHub 更新源需要用户自行提供并保存访问令牌。
- 访问令牌应按最小权限原则配置，不应要求 GitHub 用户名和密码。

## 20. 验收标准

- 程序能启动、显示主界面、显示托盘图标。
- 单实例运行正常，再次启动能激活已有窗口。
- 程序、目录、网址三类条目可添加、编辑、删除、启动。
- 拖放文件或目录到条目列表能自动创建条目。
- `.exe` 条目能自动使用程序图标、文件名和所在目录。
- 条目左键单击能启动。
- 条目右键菜单功能不误触发启动或添加对话框。
- 快捷键命中后能启动条目，并尽量阻止同一次按键传给系统或前台应用。
- 带 Win 键快捷键不应频繁触发开始菜单。
- 未绑定快捷键的条目可保存、加载和运行。
- 设置项修改后能立即生效并持久保存。
- 亮色、暗色、跟随系统主题可用。
- 中文、英文可动态切换。
- 顶部分类、二级分栏、条目布局符合四列紧凑密度。
- 吸附隐藏和边缘唤出稳定可用。
- 安装版和便携版都可检查更新并完成升级。
- 便携版升级后目录名不变，文件被正确替换。
- 关于对话框显示正确版本号。
- GitHub Release latest 指向最新版本，客户端能检查到最新版本。

- 编写内核级键盘过滤驱动。
- 保证拦截所有系统保留快捷键。
- 强制禁用其他应用已经注册或占用的快捷键。
- 对 GitHub Actions 免费额度之外的全量频繁构建做强依赖。
